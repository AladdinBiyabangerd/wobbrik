This is a controlled idle loop with identity-set instrumentation, not a device frame-rate, battery or full-process heap benchmark. The original sample cost was already far below multi-second delays. Online snapshot now returns its immutable current object unless the camera changes. Local snapshot compares immutable scene identity and all changing presentation fields before reusing its last snapshot. Existing snapshots held by consumers stay immutable. No active physics stepping, pause/resume clocks, terminal storage, finish/abandon dispatch or exact Ready/session validation was changed. The display-frame loop is retained intentionally: canonical recovery identity and lifecycle revocation are still sampled as before. This removes redundant allocation, not display-frame wakeups.

Native API34 cold baseline: the three current ApprovedArt helper calls blocked composition375ms on the main thread (4game atlases,14window sprites,68cosmetics). The authenticated root now prepares immutable APK groups via Dispatchers.IO, concurrently with recovery. InitialAccountSync's decision/gate is unchanged. Home uses a separate resource cutout and is not gated on these atlases; neither are Profile, Achievements, Leaderboard, Settings or unrelated routes. Only game/city/inventory/parts/collection/market/market-own wait for the bundles they consume. Their native shell stays interactive and Play is temporarily disabled while art is unavailable; failed decode has retry, cancellation cannot publish a completed old producer. The final art/metadata/crops are unchanged. A volatile completed flag avoids a warm-root loading flash; only complete successful preparation sets it. Partial group successes remain safely reusable on retry. Synchronous raw getters remain for already-ready content and isolated callers; direct standalone screen consumers still need their own readiness boundary.

Preparing at authenticated entry makes the same10bitmap/~60MiB groups eager even if this process only visits Home/Profile. It retains no Activity/account/catalog data and never grants authority; no memory-reduction claim. The UI is responsive while IO decoding runs, but cold first usable-art time is not eliminated.
